# V2 架构

## 原则

V2 采用“模块化单体核心 + 独立设备网关”的起步形态。交易一致性优先的租户、资产、订单、计费、支付、
账务和运营能力留在同一核心进程与数据库事务中；长连接和协议解析独立部署，避免设备流量影响用户 API。
达到明确的组织或容量边界后，再从模块边界拆分服务，不预先承担微服务分布式事务成本。

## 运行链路

1. 微信小程序通过平台适配层完成登录，业务 API 只接收平台内部身份；支付宝后续实现同一适配契约。
2. 客户端只提交幂等键和充电口；租户与客户来自已验证令牌，费率来自充电口当前配置，避免越权指定身份或价格。数据库锁定充电口并原子写入订单、会话、设备命令和 outbox。
3. 异步发布器把设备命令投递至 NATS JetStream；设备网关向在线连接下发并持久化 ACK。
4. 设备上报先通过双向 TLS、消息 HMAC、时间窗和 Valkey nonce 检查，再进入事件流。
5. 会话结束后，可信计量样本驱动计费；支付回调验签且幂等，账务以借贷平衡分录入账。

微信支付通道使用官方 APIv3 SDK生成小程序 JSAPI 参数，并对支付/退款回调的原始报文验签和解密。商户配置按租户
读取，私钥、APIv3 密钥及平台公钥只通过 `env:PREFIX` 秘密引用解析，不写入数据库或日志。

## 数据隔离

所有租户业务表都带 `tenant_id`。普通账号从已验证 JWT 的 `tenant_ids` 声明和数据库有效成员关系共同确定可访问租户，
登录后的会话引导接口返回数据库中的权威租户列表，管理端不能直接把可能过期的令牌声明当作当前租户。数据库事务设置
`app.tenant_id`，PostgreSQL RLS 再次强制过滤。后台任务必须按消息携带的可信租户标识开启独立事务。
生产数据库必须将迁移账号与运行账号分离：迁移账号拥有 DDL 权限，应用使用非超级用户、非表所有者账号，
且不得授予 `BYPASSRLS`。本地 Compose 为方便初始化使用单一超级用户，只允许用于开发环境，不能照搬到生产。
租户既可由具有 `platform_admin` 权限的平台控制面开通，也可由仅允许 `SCOPE_internal` 的自动化接口开通；公网后台不提供“抢占首个管理员”的匿名入口。平台开通租户时同步创建首位管理员身份、要求首次改密、写入成员关系与审计记录，失败时补偿刚创建的身份。
平台总管理员是数据库中唯一的上游控制面身份，使用显式 `PLATFORM_SUPER_ADMIN` 平台角色；租户内 `TENANT_ADMIN` 角色永远不会自动升级为平台管理员。启动过程只在数据库尚无密码散列时写入一次性初始密码，不会在重启时覆盖管理员已经修改的密码。
可从会话引导接口选择任一有效生产租户，并以平台级身份执行上游管理，不伪装成下游租户成员。

内置后台账号采用管理员分配制：普通后台员工不能自行注册。账号创建或重置时生成随机临时密码且只向当前管理员显示一次，首次登录必须改密，日常也可在账号安全页主动改密。密码以自描述 bcrypt 散列保存，连续失败触发临时锁定；短期访问令牌配合轮换刷新令牌，检测到刷新令牌复用会撤销整个令牌族。数据库账号状态和 `auth_version` 会在每次管理请求中复核，因此退出、改密、停用或重置后旧访问令牌立即失效。邀请有效期、成员状态和 JWT 租户声明共同参与租户授权；登录事件和敏感账号操作写入审计。登录事件与已经过期的管理端/小程序刷新令牌按统一配置每日清理，避免身份数据无限增长。需要集中 MFA、邮件找回或企业人员生命周期时，可切换外部 OIDC，业务数据模型不变。

## 渠道组织与收益关系

平台运营方是跨租户的上游主体。每个租户对应一个真实的一级经营组织，类型可以是一级分包商、区域运营商或直营网点；租户内可建立二级合作商或场地方。场站必须归属一个有效组织，充电桩和端口通过场站继承组织归属，终端用户按其真实订单关联到经营组织。一级组织直接持有的场站视为自营场站。

组织层级不替代租户隔离：下游组织不能突破所在租户的数据边界。结算规则绑定组织，一级组织规则覆盖该租户全部经营数据，二级组织规则只归集本组织场站产生的成功支付与退款。结算账期按 `Asia/Shanghai` 业务日切分，只计成功的支付或扣款并排除预授权。平台服务费支持比例基点和每账期固定费用，先从组织交易净额扣除，再按受益方比例生成应结金额；原始交易净额、平台服务费和应结金额分别固化在结算单中并进入审计链路。
平台控制面按租户逐个进入受 RLS 保护的事务读取汇总，不通过关闭隔离策略获得全库数据。平台“今日净收”只统计成功的支付/扣款并扣除当日成功退款，排除预授权和关闭交易；中国首发按 `Asia/Shanghai` 自然日统计。平台服务费取已确认、付款中和已付款结算单，待结金额单独列示，避免把草稿结算误报为收入。
这个平台级访问不依赖任何默认租户或 `tenant_ids`。外部 OIDC 若要启用平台控制面，必须由可信身份管理员显式签发 `platform_admin` 权限；普通账号仍严格执行令牌、成员关系和邀请有效期校验，已停用的成员关系不会被绕过或自动恢复。

## 扩容

- 核心 API 无状态水平扩容；写一致性由 PostgreSQL 事务、唯一约束和行锁保证。
- 设备网关按连接数水平扩容；NATS 将命令广播到各网关，持有目标连接的实例完成下发。Valkey 保存防重放
  nonce 与加密设备凭据，事件和命令由 JetStream 解耦。
- 计量表按月或按周分区；超过单库安全容量后按租户/区域分片。
- PostgreSQL、Valkey、NATS 在正式生产使用托管或三节点高可用，不与应用争抢同一台主机资源。
- NATS 生产集群必须启用账号权限、TLS 与 JetStream 副本；设备凭据应存入 KMS/密钥服务并支持轮换，不能使用环境变量明文清单长期管理。
- 当前设备共享密钥由核心服务随机生成、AES-256-GCM 加密后写入 Valkey，网关按需解密并短时缓存；加密主密钥必须由生产秘密管理系统注入并定期轮换。

## 平台前端

管理端采用 Vue 3 + TypeScript。微信端采用原生小程序，保持零运行依赖和最小包体；支付宝端后续使用独立薄壳。
两个小程序共用同一 OpenAPI 契约、业务状态定义和测试用例，登录、支付、手机号、订阅消息、地图等能力放在各自
`platform` 适配层中。当前微信端保持原生实现，以减少运行时和构建供应链体积。
