# 商用交付路线

## 已进入 V2 基线

- 多租户、场站、设备、12 口连接器、客户、费率、订单、会话、计量、设备命令。
- 支付、退款、双式账务、审计、幂等、outbox/inbox 数据基础。
- 订单创建到桩端启动、ACK、计量、停止、计费和端口释放的事件闭环。
- PostgreSQL RLS、JWT 租户声明校验、设备 mTLS/HMAC/nonce 防重放。
- 管理 Web、原生微信小程序和真实设备协议网关；支付宝通过相同 API 契约追加客户端与支付适配器。
- 微信小程序真实身份交换、令牌轮换，管理 Web OIDC PKCE 与租户 RBAC。
- 微信支付 APIv3 官方 SDK 下单、支付/退款回调验签解密和内部账务入账。
- 运营后台已覆盖渠道组织树、组织归属资产、费率、订单、支付退款、按组织分成与平台服务费结算、告警工单、权限与审计。

## 接入真实桩前

1. 根据厂家协议文档实现二进制协议适配器、心跳和固件能力矩阵。
2. 用真机完成弱网、乱序、重复、断电、拔枪、异常电流和急停用例。
3. 将当前 AES-256-GCM 加密凭据的主密钥托管到 KMS/Secrets Manager，并签发独立设备证书。
4. 配置正式 OIDC/管理员 MFA，并按实际岗位验收现有租户角色矩阵。

## 开始真实收款前

1. 填入微信商户凭据和正式回调域名，完成证书/公钥轮换与真实商户验收。
2. 使用真实日账单验收现有逐笔对账、双式账务和差错工单流程。
3. 对接实际付款渠道的分账/转账、电子回单和提现审批；组织归集、账期、平台服务费及结算单已实现。
4. 微信首发稳定后追加支付宝小程序壳和经安全审计的支付宝支付适配器，复用统一订单与账务域。

## 正式生产前

完成 [production-readiness.md](production-readiness.md) 的全部门禁。未完成门禁时只允许隔离试点数据，
不得开启正式商户号或面向公众运营。
